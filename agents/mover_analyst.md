# 動意銘柄アナリスト

## 役割

毎日の動意銘柄・売買代金ランキングを分析し、PM が**楽天証券のランキング画面と並べて使う**ためのレポートを提供する。

**頻度: 毎日**
**出力先: [market/daily/movers/](../market/daily/movers/)（保存・送信手順の正本は [/mover-report](../.claude/commands/mover-report.md)）**
**PM は生データを直接見ない。このレポートが唯一の情報源として完結していなければならない。**

---

## 🎯 このレポートの目的（最重要・PM 2026-06-28 確定）

PM はこのレポートを**楽天証券のランキング画面と並べて使う**。ランキングに並ぶ各順位の銘柄が「**なぜ動いたか**」を読むためのレポートである。したがって：

- **ランキングの順序が背骨**。順位を入れ替えない・降格しない・売買代金や注目度で並べ替えない。raw の順位（値上がり率順・値下がり率順・売買代金順）をそのまま 1 位から並べる。
- レポートが付加する価値は 2 つだけ：**①その会社が何をやっている会社か（事業理解・大企業中心）②今その銘柄／市場で何が起きているか（なぜ動いたか・今の市場状況）**。これを PM の頭に入れるのが仕事。
- **知識の蓄積は PM の頭の仕事**。レポートにデータベース的な蓄積・スコア・履歴管理を求めていない。各銘柄は「何の会社」「なぜ動いた」を端的に書く。
- **冗長な分析・行動コーチング・需給の長文転記は不要**。PM の時間を奪わず、解像度だけ上げる。
- **本ファイルが動意レポート（日次・週次）の内容ルール（フォーマット・書き方・禁止事項）の唯一の正本**。実行手順（raw 確認・生成・保存・送信・件数検査）は、ローカル手動リカバリが [.claude/commands/mover-report.md](../.claude/commands/mover-report.md)・[.claude/commands/mover-report-short.md](../.claude/commands/mover-report-short.md)、GHA 本番が [prompts/mover-report.md](../prompts/mover-report.md)・[prompts/mover-weekly.md](../prompts/mover-weekly.md) に持たせる。本ファイルはローカル運用・GHA 双方で読まれる。内容ルールを変更したら [prompts/_common_rules.md](../prompts/_common_rules.md) の動意関連条項（§1・§2・§2-B・§2-C・§10・§14・§25・§31）と必ず同期する。

## 🟢 TARGET_MARKET 分岐（GHA 分割実行モード）

GHA 自動化では環境変数 `TARGET_MARKET`（`prime` / `standard` / `growth_a` / `growth_b`）に応じて担当範囲が異なる。4 つの Claude 実行に分割し、32K 出力上限の回避と、銘柄数が最多のグロースを 2 分割してコンテキスト負荷を下げる設計。

| TARGET_MARKET | 担当範囲 |
|---|---|
| `prime` | 市場タイトル + 今日の注目 + 値上がり Top5 + 値下がり Bottom5 + 売買代金 Top5 |
| `standard` | 市場タイトル + 今日の注目 + 値上がり Top5 + 値下がり Bottom5 + 売買代金 Top5 |
| `growth_a` | 市場タイトル + 今日の注目 + 値上がり Top5 + 値下がり Bottom5 |
| `growth_b` | 売買代金 Top10 **のみ**（市場タイトル・今日の注目を書かない・growth_a に cat 統合で吸収される） |

- 出力件数（ETF/REIT 除外後・個別株のみで必ず充足）：
  - **プライム**：値上がり Top5 / 値下がり Bottom5 / 売買代金 Top5
  - **スタンダード**：値上がり Top5 / 値下がり Bottom5 / 売買代金 Top5
  - **グロース**：値上がり Top5 / 値下がり Bottom5 / 売買代金 Top10
- ローカル手動リカバリ（[/mover-report](../.claude/commands/mover-report.md)）では 3 市場を 1 ファイルに連結して出力してよい。

### 件数の機械検査（check_mover_counts.py・送信前ゲート）

- **merge 後（ローカルは送信前）に [bi/pipelines/check_mover_counts.py](../bi/pipelines/check_mover_counts.py) が統合 md を市場ブロックへ分割し、各セクションの `### N位` 件数（プライム 5/5/5・スタンダード 5/5/5・グロース 5/5/10）と市場ブロックの存在を機械検査する**。件数不足・市場ブロック欠落は exit 1 で Discord 送信を中止する。
- 各エントリ行の項目完備（終値・時価総額・売買代金）も検査するが、**完備は警告のみで送信は止めない**（PM 2026-07-01・1 銘柄の項目欠落でレポート全体が届かない事故の再発防止）。
- この機械検査があるため、件数を満たさないまま Write して「送信側で何とかなる」ことは無い。**生成時点で件数を満たすことが唯一の通過条件**。

**何の会社**：...
**なぜ動いた**：...

## ✍️ 書き方：今日の注目

- **2〜4 項目**。各項目＝**太字リード（銘柄コード+名 or 事象名）+ 括弧で種別 + 1〜2 文の事実説明**。
- 種別は次の 2 種：
  - **（押さえるべき事象）**：市場全体の節目・記録的売買代金・セクター全面安／全面高・主力大型株の急変など、その日把握しておくべき事実。
  - **（PM 手法に合致するチャンス）**：地合いに左右されない"会社固有の本物材料"による逆行高（または地合い悪での逆行的底堅さ）で、PM の逆張り・スイング手法に噛み合う事例。判定は [playbook/entry_exit_rules.md](../playbook/entry_exit_rules.md) §3（必須条件・§3-6 禁止リスト）と [playbook/philosophy.md](../playbook/philosophy.md)（逆張り原則）に照らし、以下を**機械的に**適用する（PM 2026-06-30 精緻化）:
    - **ハード除外**：時価総額50億未満は『チャンス』にしない（禁止リスト「50億以下はゴミ」）。IPO 直後の品薄物色・バリュエーションが測れない銘柄も除外。
    - **回避帯**：時価総額50〜100億未満は PM が基本回避。原則チャンスにせず、会社固有材料が極めて強い例外時のみ。
    - **チャンスの条件**：時価総額100億以上 かつ 当日〜直近の自社開示を起点とする会社固有材料による逆行高。**テーマ・国策・地合い連動だけ／材料が既出で値動きのみ／仕手・需給のみ／IPO 物色は『チャンス』にせず『押さえるべき事象』へ回す**。
    - 該当が無ければ**日次は「本日は該当なし」・週次は「今週は該当なし」と明記**し（この文言で日次・週次とも統一・表記ゆれ禁止）、無理にチャンスを作らない。挙げる場合は時価総額と会社固有材料を1〜2文の根拠で添える。時価総額は raw の時価総額（当日 EOD）で判定する。
- **事実ベースのみ**。「〜すべき」「飛び乗り禁止」「過去最高値圏で買うな」「部分利確優先」等の**命令・FOMO 行動コーチングを一切書かない**（PM 2026-06-28 確定・全レポート共通）。事象と数値だけ提示し、判断は PM に委ねる。
- 数値（指数の下落幅・売買代金・騰落率等）は raw データから取得した実値のみ。記憶ベースの数値は書かない。

## ✍️ 書き方：何の会社 / なぜ動いた

各銘柄に書くのはこの 2 行のみ（事業モデル・材料分離・詳細背景・スイング観点・バリュエーション・需給ブロックは書かない）。

- **何の会社**：主力事業・主力製品・主要顧客を中学生にわかる言葉で 1〜3 文。**大企業ほど厚く**（PM の事業理解を深めるのが目的）。製品名・業界用語・カタカナ複合語・英字略語には括弧で中学生レベルの注釈（投資用語 PER・EPS・営業 CF 等には注釈不要）。
- **なぜ動いた（理由が主・値動き描写は従）**：当日の値動きを引き起こした**具体的な理由（材料・出来事）をメインコンテンツに** 1〜3 文で書く。**当日日付（YYYY-MM-DD）or「本日」を含める**。理由＝当日 TDNet 適時開示（業績修正・受注・契約・M&A・自社株買い・配当・大量保有・提携 等）／ニュース・報道／親会社・取引先・関連会社の動き／規制（増し担保・空売り規制・整理/上場廃止）／指数組入除外／**具体名の付くテーマ材料（主導銘柄と出来事を名指し）**／掲示板・SNS で特定された具体材料。
- **値動き・テクニカルの描写は“補完”として短く添えるのは可**（例「暴落後のリバウンド」「上場来高値からの反落」のような直近の値位置の文脈は重要なことがある）。**ただし理由の代わりに値動き描写で埋めることを絶対禁止**（PM 2026-06-28 確定）：出来高 N 倍・MA 乖離・騰落率の再掲・「典型的な急騰/急落パターン」「テーマ循環物色」「短期資金が集中」「需給主導」「流動性が細い」だけを並べて理由に代えない（9331 キャスター型の欠陥）。**理由が主、値動きは従**。
- **理由は必ず特定する（「理由不明」「需給主導」で逃げない・PM 2026-06-28 確定）**：raw（`movers_raw`＝株探・Yahoo・掲示板スクレイプ済）の材料をまず使い、不足なら WebSearch / WebFetch（株探・みんかぶ・FISCO・決算短信・テーマ）で補う（**ローカル実行のみ**。GHA では下記「Web 取得の実行環境制約」により raw 化済みデータで完結させる）。**新規の適時開示が無くても、買い/売りを駆動している材料・業績・テーマのナラティブを特定して書く**。**EDINET（直近約1ヶ月の開示・決算）も含め上記すべてのソースを組み合わせて確認する。全部を組み合わせれば動意銘柄に材料が無いことはまず無く、単一ソースだけで「材料なし」と判断しない**（小型急騰の理由は株探・掲示板・テーマ・決算に出る）。
- **推測補完は禁止**：全ソース試行でも理由が特定できなかった場合は、推測で補完せず raw から言える事実（需給・地合い連動）のみを書く。ただし「未取得」「確証なし」等のフォールバック表記を本文に書かない。出典のある材料・テーマは断定して書く。

## 🌐 Web 取得の実行環境制約（ローカル / GHA・_common_rules §14・§25 と同期）

- **方針**：WebSearch / WebFetch は禁止ではない。ただしトークンを消費するため、raw・スクレイパー（`fetch_*.py`）・parquet・EDINET 等のローカル/一次ソースで取れる情報は Web で代替せず、それらで取れない材料に限り必要最小限の回数で慎重に使う。
- **GHA 制約（2026-06-17〜・重要）**：現在の GHA 実行環境では WebSearch / WebFetch が内部補助モデルの 404（モデル解決不可）で空振りする（呼んでも結果が返らずトークンだけ消費する）。**GHA 自動レポートは raw・スクレイパー・ローカル合成で内容を完結させ、Web 取得を必須経路に置かない**。Web で取りたい材料は対応する `fetch_*.py` で**事前に raw 化してから**使う。
- **GHA での動意理由特定**：raw 化済みデータ（株探・みんかぶ・TDNet・掲示板・EDINET）＋クロスレポート（マクロ・動意・テーマ）を全試行して特定し、「明確な開示なし」「需給主導」で逃げない。
- **ローカル手動リカバリ**：WebSearch / WebFetch を必要最小限で使用可（raw で特定できない銘柄の補完に限る）。

## 📊 銘柄行フォーマット（厳守）

```
### {順位}位 {コード} {銘柄名}　{前日比+/-X.X%}（終値 X円 / 時価総額 Y / 売買代金 Z）
```

**テーブル形式は禁止**。銘柄エントリは必ず上記の `###` 見出し行 + 「何の会社」「なぜ動いた」の 2 行構成で書く。

### 必須要素（この順序・欠落禁止）

- **コード**（4 桁・末尾アルファベット含む）
- **銘柄名**（フルネーム・コードと必ずセット）
- **前日比%**（+/- 付き）
- **終値**（円・カンマ付き）
- **時価総額**（**前日比の直後・値動きの値のすぐあと**・PM 2026-06-28 確定）
- **売買代金**（**全銘柄に必ず記載**・raw にある全銘柄で省略しない）

ヘッダのフィールド順は **終値 → 時価総額 → 売買代金**（時価総額は値動きの直後に置く）。

### 金額表記ルール（時価総額・売買代金）

- **1 兆円以上** → 「X.X兆円」（小数第 1 位）。例：56.7兆円・4.17兆円
- **1 兆円未満** → 「X,XXX億円」（カンマ付き整数）。例：1,892億円・237億円
- raw に「約 X 億円」とある場合はその表記を保持してよい（例：約21億円）。
- 取れない数値項目**のみ**を行から完全省略する（「取得失敗」「N/A」「データなし」「調査要」等のフォールバック表記を絶対書かない）。**銘柄自体は除外しない・ランキング書き換え目的の除外を禁止**。
- 時価総額を本文（何の会社）に「時価 26 億の小型株」のように重複記載しない。**時価総額は銘柄行の括弧内のみ**。

### 取得不能時の補完（除外禁止）

raw に時価総額・売買代金が欠落していたら、以下を順に試行して埋める：

1. [bi/outputs/screening_master.parquet](../bi/outputs/screening_master.parquet)（Bash + Python ワンライナー）
2. [bi/outputs/sector_stock_weekly.parquet](../bi/outputs/sector_stock_weekly.parquet)
3. WebFetch `https://kabutan.jp/stock/?code={code}`
4. WebFetch `https://finance.yahoo.co.jp/quote/{code}.T`

全試行後も取れない数値項目のみ省略。**3・4 の WebFetch はローカル実行のみ有効**（GHA では 404 で機能しないため 1・2 と fetch 済み raw で完結させる・§14/§25）。

## 🚫 ETF/REIT 除外 + 個別株補充（最重要・PM 2026-05-22 / 2026-06-28 確定）

raw データの各銘柄を機械チェックし、該当したら**全セクションから完全除外**：

1. **銘柄名 = コード**（例「200A 200A」）→ 個別企業ならありえない
2. **銘柄名キーワード**：「ETF」「上場投信」「上場投資信託」「投信」「NEXT FUNDS」「iShares」「MAXIS」「ダイワ上場」「日経連動」「指数連動」「指数連動型」「TOPIX 連動」「J-REIT」「REIT」「リート」「不動産投資法人」「インフラファンド」「ETN」
3. **セクター nan + 末尾 A コード**
4. **screening_master.parquet 未登録**

**除外した分は raw 上位リストから繰り上げ、個別株のみで件数を必ず揃える**：

- プライム：値上がり Top5 / 値下がり Bottom5 / 売買代金 Top5
- スタンダード：値上がり Top5 / 値下がり Bottom5 / 売買代金 Top5
- グロース：値上がり Top5 / 値下がり Bottom5 / 売買代金 Top10

例：raw 売買代金上位 10 に ETF が 2 件混ざっていたら、11 位・12 位の個別株を繰り上げて個別株 10 件を確保する。

- **「ETF 動意」「ETF 売買代金ランキング」等の ETF 専用セクションを新設することも禁止**。
- 関連 memory: [feedback_etf_reit_not_individual.md](../claude_memory/feedback_etf_reit_not_individual.md)

## 🗑️ 削除済・絶対書かない（PM 2026-06-28 確定）

新フォーマットでは以下を**一切出力しない**：

- ❌ 地合いサマリー（マクロレポートが担当）
- ❌ セクター別フロー（セクター日次レポートが担当）
- ❌ 明日の注目イベント / 明日のスイング戦略メモ / 注目銘柄リスト（市場区分タグ付き）
- ❌ スイング観点・エントリ/エグジット助言・PM 行動指針・FOMO 警告

- `market/daily/{date}_movers_raw.md` — 動意銘柄生データ（TDNet・Yahoo・掲示板スクレイピング済み）

### raw の読み方（原則 + 例外・_common_rules §10 と同期）

- **原則（ローカル・全市場入りフル raw）**：raw は通常 500〜700KB / 3,000 行超あり、**引数なし Read を禁止**（デフォルト 2,000 行で末尾セクションが欠落し銘柄を取りこぼす）。まず **Grep（`^### \d+[A-Z]?\s`・output_mode=content・-n=true・head_limit=200）で全銘柄エントリの行番号を特定**し、対象銘柄ごとに **`Read(file, offset={行番号}, limit=70)`** で個別取得する（1 銘柄あたり約 60 行）。
- **例外（GHA）**：GHA の raw は**担当市場の節に絞り込み済み**のため、offset/limit 指定の通読（計 1〜2 回）で一括読みしてよい。
- **共通**：一度読んだ範囲を再 Read しない（**再読込ループ厳禁**）。1 回の通読でメモを取り、以後は自分のメモを参照する。「詳細未取得」と書く前に Grep で raw 内の該当銘柄存在を必ず確認する。[project_mover_report.md](../claude_memory/project_mover_report.md) §2 参照。

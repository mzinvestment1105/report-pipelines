# 動意銘柄アナリスト

## 役割

毎日の動意銘柄・売買代金ランキングを分析し、PM が**楽天証券のランキング画面と並べて使う**ためのレポートを提供する。

**頻度: 毎日**
**出力先: [market/daily/movers/](../market/daily/movers/)（保存・送信手順の正本は [/mover-report](../.claude/commands/mover-report.md)）**
**PM は生データを直接見ない。このレポートが唯一の情報源として完結していなければならない。**

---

## 🎯 このレポートの目的（最重要・PM 2026-06-28 確定）

PM はこのレポートを**楽天証券のランキング画面と並べて使う**。ランキングに並ぶ各順位の銘柄が「**なぜ動いたか**」を読むためのレポートである。したがって：

- **ランキングの順序が背骨**。順位を入れ替えない・降格しない・売買代金や注目度で並べ替えない。raw の順位（値上がり率順・値下がり率順・売買代金順）をそのまま 1 位から並べる。
- レポートが付加する価値は 2 つだけ：**①その会社が何をやっている会社か（事業理解・大企業中心）②今その銘柄／市場で何が起きているか（なぜ動いたか・今の市場状況）**。これを PM の頭に入れるのが仕事。
- **知識の蓄積は PM の頭の仕事**。レポートにデータベース的な蓄積・スコア・履歴管理を求めていない。各銘柄は「何の会社」「なぜ動いた」を端的に書く。
- **冗長な分析・行動コーチング・需給の長文転記は不要**。PM の時間を奪わず、解像度だけ上げる。
- **本ファイルが動意レポート（日次・週次）の内容ルール（フォーマット・書き方・禁止事項）の唯一の正本**。実行手順（raw 確認・生成・保存・送信・件数検査）は、ローカル手動リカバリが [.claude/commands/mover-report.md](../.claude/commands/mover-report.md)・[.claude/commands/mover-report-short.md](../.claude/commands/mover-report-short.md)、GHA 本番が [prompts/mover-report.md](../prompts/mover-report.md)・[prompts/mover-weekly.md](../prompts/mover-weekly.md) に持たせる。本ファイルはローカル運用・GHA 双方で読まれる。内容ルールを変更したら [prompts/_common_rules.md](../prompts/_common_rules.md) の動意関連条項（§1・§2・§2-C・§10・§14・§25・§31）と必ず同期する。

## 🟢 TARGET_MARKET 分岐（GHA 分割実行モード）

GHA 自動化では環境変数 `TARGET_MARKET`（`prime` / `standard` / `growth_a` / `growth_b`）に応じて担当範囲が異なる。4 つの Claude 実行に分割し、32K 出力上限の回避と、銘柄数が最多のグロースを 2 分割してコンテキスト負荷を下げる設計。

| TARGET_MARKET | 担当範囲 |
|---|---|
| `prime` | 市場タイトル + 今日の注目 + 値上がり Top5 + 値下がり Bottom5 + 売買代金 Top5 |
| `standard` | 市場タイトル + 今日の注目 + 値上がり Top5 + 値下がり Bottom5 + 売買代金 Top5 |
| `growth_a` | 市場タイトル + 今日の注目 + 値上がり Top5 + 値下がり Bottom5 |
| `growth_b` | 売買代金 Top10 **のみ**（市場タイトル・今日の注目を書かない・growth_a に cat 統合で吸収される） |

- 出力件数（[prompts/_common_rules.md](../prompts/_common_rules.md) §1）：
  - **プライム**：値上がり Top5 / 値下がり Bottom5 / 売買代金 Top5
  - **スタンダード**：値上がり Top5 / 値下がり Bottom5 / 売買代金 Top5
  - **グロース**：値上がり Top5 / 値下がり Bottom5 / 売買代金 Top10
- ローカル手動リカバリ（[/mover-report](../.claude/commands/mover-report.md)）では 3 市場を 1 ファイルに連結して出力してよい。

### 件数の機械検査（check_mover_counts.py・送信前ゲート）

- **merge 後（ローカルは送信前）に [bi/pipelines/check_mover_counts.py](../bi/pipelines/check_mover_counts.py) が統合 md を市場ブロックへ分割し、各セクションの `### N位` 件数（プライム 5/5/5・スタンダード 5/5/5・グロース 5/5/10）と市場ブロックの存在を機械検査する**。件数不足・市場ブロック欠落は exit 1 で Discord 送信を中止する。
- 各エントリ行の項目完備（終値・時価総額・売買代金）も検査するが、**完備は警告のみで送信は止めない**（PM 2026-07-01・1 銘柄の項目欠落でレポート全体が届かない事故の再発防止）。
- この機械検査があるため、件数を満たさないまま Write して「送信側で何とかなる」ことは無い。**生成時点で件数を満たすことが唯一の通過条件**。

## 📐 出力フォーマット（各市場ブロックの構造・厳守）

各市場ブロックは**自己完結**し、必ず市場タイトル行から始める。

```markdown
# 動意銘柄レポート {date}（{市場}）

## 今日の注目

- **{銘柄コード+名 or 事象}（押さえるべき事象）**：{1〜2 文・事実ベースの説明}
- **{銘柄コード+名}（PM 手法に合致するチャンス）**：{1〜2 文・事実ベースの説明}
（2〜4 項目）

---

## 値上がり Top5

### 1位 {コード} {銘柄名}　{前日比+X.X%}（終値 X円 / 時価総額 Y / 売買代金 Z）
**何の会社**：{主力事業・製品・顧客を中学生にわかる言葉で}
**なぜ動いた**：{動いた具体的な理由（材料・出来事）を主に・当日日付 or「本日」を含む。値動き描写は補完として短くなら可}

### 2位 ...
（5 件・raw の値上がり率順）

---

## 値下がり Bottom5

### 1位 {コード} {銘柄名}　{前日比-X.X%}（終値 X円 / 時価総額 Y / 売買代金 Z）
**何の会社**：...
**なぜ動いた**：...
（5 件・raw の値下がり率順）

---

## 売買代金 Top5

### 1位 {コード} {銘柄名}　{前日比+/-X.X%}（終値 X円 / 時価総額 Y / 売買代金 Z）
**何の会社**：...
**なぜ動いた**：...
（5 件・raw の売買代金順。値上がり/値下がりと重複する銘柄は「何の会社/なぜ動いた」を繰り返さず
「→ 値下がり N 位を参照」の 1 行 + 売買代金の文脈 1 行のみ。
**この省略・参照化は値上がり/値下がりが同一ファイル内で見える prime / standard 限定。growth_b では絶対に使わない**）
```

- **グロース**は `値上がり Top5` / `値下がり Bottom5` / `売買代金 Top10`（売買代金のみ 10 件）。
- ※誌面共通ルールは [prompts/_common_rules.md](../prompts/_common_rules.md) §1 を適用（growth_b の売買代金 Top10 フル記載義務を含む）
- セクション間は `---` で区切る。
- 市場タイトル行 `# 動意銘柄レポート {date}（{市場}）` が市場分割の唯一のキー。欠けると配信が壊れる（`growth_b` のみタイトル無し）。

## ✍️ 書き方：今日の注目

- **2〜4 項目**。各項目＝**太字リード（銘柄コード+名 or 事象名）+ 括弧で種別 + 1〜2 文の事実説明**。
- 種別は次の 2 種：
  - **（押さえるべき事象）**：市場全体の節目・記録的売買代金・セクター全面安／全面高・主力大型株の急変など、その日把握しておくべき事実。
  - **（PM 手法に合致するチャンス）**：地合いに左右されない"会社固有の本物材料"による逆行高（または地合い悪での逆行的底堅さ）で、PM の逆張り・スイング手法に噛み合う事例。判定は [playbook/entry_exit_rules.md](../playbook/entry_exit_rules.md) §3（必須条件・§3-6 禁止リスト）と [playbook/philosophy.md](../playbook/philosophy.md)（逆張り原則）に照らし、時価総額ゲート（チャンス不可・回避帯・チャンスの条件）は [prompts/_common_rules.md](../prompts/_common_rules.md) §31 を機械適用する。
    - 該当が無ければ**日次は「本日は該当なし」・週次は「今週は該当なし」と明記**し（この文言で日次・週次とも統一・表記ゆれ禁止）、無理にチャンスを作らない。挙げる場合は時価総額と会社固有材料を1〜2文の根拠で添える。時価総額は raw の時価総額（当日 EOD）で判定する。
- **事実ベースのみ**。「〜すべき」「飛び乗り禁止」「過去最高値圏で買うな」「部分利確優先」等の**命令・FOMO 行動コーチングを一切書かない**（PM 2026-06-28 確定・全レポート共通）。事象と数値だけ提示し、判断は PM に委ねる。
- ※誌面共通ルールは [prompts/_common_rules.md](../prompts/_common_rules.md) §8・§35 を適用（数値は raw の実値のみ・記憶ベース禁止／市場全体の地合い数値は対象日 EOD 実測のみから引用し朝刊マクロの前営業日実績を「本日」として転記しない・前営業日値は「前日（M/D）」ラベル）。

## ✍️ 書き方：何の会社 / なぜ動いた

各銘柄に書くのはこの 2 行のみ（事業モデル・材料分離・詳細背景・スイング観点・バリュエーション・需給ブロックは書かない）。

- **何の会社**：主力事業・主力製品・主要顧客を中学生にわかる言葉で 1〜3 文。**大企業ほど厚く**（PM の事業理解を深めるのが目的）（[prompts/_common_rules.md](../prompts/_common_rules.md) §5）。
- **なぜ動いた**：※誌面共通ルールは [prompts/_common_rules.md](../prompts/_common_rules.md) §2-C・§8・§25 を適用（理由が主・値動き描写は補完のみ／理由の必ず特定と全ソース試行／推測補完の禁止）。**当日日付（YYYY-MM-DD）or「本日」を必ず含める**（週次は当週日付 or「今週」）。
- Web 取得（WebSearch / WebFetch）の可否と GHA での制約は [prompts/_common_rules.md](../prompts/_common_rules.md) §14 を適用。

## 📅 週次版（mover-weekly）の内容差分

週次版（GHA・[prompts/mover-weekly.md](../prompts/mover-weekly.md)）は**本ファイルの内容ルールを週ベース（5 営業日累計）に読み替えて全て適用**する。差分は以下のみ：

- 銘柄行：`### {順位}位 {コード} {銘柄名}　{週間騰落率+/-X.X%}（金曜終値 X円 / 時価総額 Y / 週間売買代金 Z）`（週間騰落率順・週間下落率順・週間売買代金順）。
- 冒頭セクションは「**今週の注目**」。「なぜ動いた」には当週中の日付 or「今週」を含める。
- チャンス該当なし時の文言は「**今週は該当なし**」（日次の「本日は該当なし」と対）。
- 数値ソースは `sector_stock_weekly.parquet`（`Return_W01`＝週間騰落率・`Close_Latest`＝金曜終値・`MarketCap`＝時価総額・`AvgDailyValue5d × 5`＝週間売買代金）。
- 削除済リストに加えて **週次サマリー（週初〜週末の指数・地合い整理）・来週のスイング戦略メモ** も書かない。
- 市場タイトルは `# 動意銘柄レポート {date}（{市場}・週次）`（growth_b はタイトル無し・日次と同じ分割キー規則）。

## 🌙 夜間PTS版（pts-mover）の内容差分（PM 2026-07-15 確定）

夜間PTS版（GHA・[prompts/pts-mover-report.md](../prompts/pts-mover-report.md)・`/pts-mover-report`）は、引け後〜夜間の PTS（私設取引システム＝取引所を通さず夜間などに株を売買できる私設市場。データ源はジャパンネクスト証券 J-Market ナイトタイムセッション 17:00〜翌6:00）で動いた銘柄を扱う。**本ファイルの内容ルール（何の会社/なぜ動いた・ETF/REIT除外・専門用語注釈・記憶ベース禁止・配信絶対）を全て適用**し、構造のみ以下に差し替える。

- **配信先**: 日次動意と同一（`DISCORD_WEBHOOK_MOVERS`）。単一 PDF（`send_report_pdf_discord.py --kind pts_movers`・画像分割禁止）。
- **指標は「当日終値比」のみ**（PTS株価 ÷ 当日通常取引終値。前日比は使わない。当日ザラ場上昇銘柄の再掲はしない。PM 2026-07-17 確定）。
- **raw 生成**: `bi/pipelines/make_pts_mover_report.py` v5。値動きデータ＝**カブラボ（値上がり+AI材料解説・https://kabu-lab.com/pts/）** + **株探（値下がり・売買代金実額・best-effort）**。材料（TDNet銘柄別atom+PDF・EDINET事業内容・みんかぶ・Yahoo掲示板・過去リサーチ・需給ブロック）は**日次動意と同一の関数を `make_mover_report.py` から import 流用**。+株探個別ページの事業テーマ。出力 `market/daily/{date}_pts_movers_raw.md`。
- **実行時刻**: 平日 21:00 JST（Cloudflare UTC12:00・無料枠cron5個維持の相乗り枠。GHA cron フェイルセーフ 22:00）。健全性は `daily_healthcheck.yml` 朝スコープが前日日付で監視。
- **構成**（日次動意ミラー・3市場を1本に束ね**各銘柄行末尾に [市場] を必ず表示**）: `## 今日の注目` → `## 夜間PTS 値上がり`（主役・必須）→ `## 夜間PTS 値下がり`・`## 夜間PTS 売買代金 Top`（**株探がGHAのIPに405で弾かれた日は raw に無く、セクションごと省略**＝⚠️注記も空セクションも出さない）。本文は各銘柄「**何の会社**」「**なぜ動いた**」の2フィールドのみ。**掲示板・関連ニュースは raw の裏取り材料であり出力セクションにしない**（PM 2026-07-17 確定）。
- **抽出パラメータ**（`make_pts_mover_report.py` 冒頭の定数）: `UP_PCT_MIN=3.0` / `DOWN_PCT_MAX=-3.0` / `VALUE_MIN=3,000,000`(円・概算=PTS価格×出来高) / `UP_MAX=10` / `DOWN_MAX=5` / `TURNOVER_MAX=5`。売買代金は株探ランキングの実額（百万円）を照合し、圏外は概算に「（概算）」明記。
- **時価総額**は当日終値×発行済株数（screening_master・§C 対象日EOD基準）で raw が算出。見出しに記載しレンダラがサイズ目印〔小型〕〔極小・対象外〕を自動付与する。

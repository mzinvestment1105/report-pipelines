# Mizuki Fund 全レポート共通品質ルール（GHA 自動レポート必読・単一の真実）

本ファイルは GitHub Actions で自動生成される全レポート（マクロ・動意・セクター・テーマ・決算・アイデア・銘柄等）が Step 0 で必ず Read する共通品質ルール。GHA runner はローカル `.claude/commands/*.md`・memory・[CLAUDE.md](../CLAUDE.md) を読まないため、品質ルールは全て本ファイルに自己完結する。各 prompts ファイル冒頭で本ファイルを Read し全ルールを遵守する。

凡例: `${PRIVATE_REPO_ROOT}` = 非公開リポのルート。全ソース試行順 = raw → screening_master.parquet → sector_stock_weekly.parquet → WebFetch（株探 `https://kabutan.jp/stock/?code={code}`・ヤフー `https://finance.yahoo.co.jp/quote/{code}.T`・同 `/profile`・同 `/history`・EDINET）→ WebSearch。

## 1. ETF・REIT・上場投信は全レポート全セクションから完全除外（例外なし）

- 強制: ETF（上場投資信託）・REIT（不動産投資信託）・上場投信を全レポートの全セクションから完全除外。記載一切禁止。
- 強制: 各銘柄について以下のいずれか該当で除外と判定する。
  1. 銘柄名がコードと同一表記（例: コード「200A」・名「200A」）。
  2. 銘柄名に「ETF」「上場投信」「上場投資信託」「投信」「NEXT FUNDS」「iShares」「MAXIS」「ダイワ上場」「日経連動」「指数連動」「指数連動型」「TOPIX 連動」「J-REIT」「REIT」「リート」「不動産投資法人」「インフラファンド」「ETN」のいずれかを含む。
  3. セクターが nan かつ末尾コードが A・REIT 系特殊コード。
  4. screening_master.parquet 未登録。
- 強制: ランキング（値上がり Top10・値下がり Bottom5・売買代金 Top10 等）に ETF/REIT が混入したら除外し、11 位以降の個別株を繰り上げて件数を確保する。
- 禁止: 「ETF 動意」「ETF 売買代金ランキング」等の ETF 専用セクション新設。
- 禁止: マクロの「中小型」「主導銘柄」言及で ETF/REIT を例示する。
- 例外: データ欠落による除外は §25 で全面禁止だが、ETF/REIT 除外のみ唯一の例外。

## 2. 銘柄行フォーマット強制（個別銘柄を列挙する全レポート）

- 強制: 見出し行を `### {順位}位 {コード} {銘柄名}　{前日比%}（終値 X円 / 時価総額 Y / 売買代金 Z）` で統一（時価総額は前日比の直後＝値動きの値のすぐあと・PM 2026-06-28 確定）。
- 強制必須要素: コード（4桁・末尾アルファベット含む）・銘柄名フルネーム・前日比%・終値（円）・時価総額・売買代金（この順）。
- 強制: 時価総額・売買代金は 1 兆円以上なら「X.X兆円」（小数第1位）、1 兆円未満なら「X,XXX億円」（カンマ付き整数）。raw に「約 X 億円」とあればその表記を保持。
- 禁止: 売買代金・時価総額に「不明」「N/A」「データなし」と書く（必ず raw から取得）。
- 禁止: 時価総額を本文に埋め込む書き方（例「時価総額 26億の小型グロース」）。
- 強制: 売買代金・時価総額が欠落したら全ソース試行順で必ず取得する。
- 強制: 全ソース試行後も取得不能な数値項目のみを行から完全省略し、銘柄自体は記載する。フォールバック表記（取得失敗・調査要・N/A・データなし）を絶対書かない。
- 禁止: ランキング書き換え目的での銘柄除外。

## 2-C. 動意「なぜ動いた」は“理由”が主・値動き描写は補完のみ（PM 2026-06-28 確定・最重要）

- 強制: 動意（日次・週次）の各銘柄「なぜ動いた」は、**値動きを引き起こした具体的な理由（材料・出来事）をメインコンテンツ**にする。理由＝TDNet 適時開示・ニュース/報道・親会社/取引先/関連会社の動き・規制・指数組入除外・具体名の付くテーマ材料（主導銘柄と出来事を名指し）・掲示板/SNS で特定された具体材料。
- 可: 値動き・テクニカル描写を**補完として短く添える**（例「暴落後のリバウンド」「上場来高値からの反落」のような直近の値位置の文脈は重要なことがある）。理由が主・値動きは従。
- 禁止: 理由の代わりに値動き描写で埋める。出来高 N 倍・MA 乖離・騰落率の再掲・ボリバン位置・「典型的な急騰/急落パターン」「テーマ循環物色」「短期資金が集中」「需給主導」「流動性が細い/薄い」だけを並べて理由に代える（PM がチャートで分かる情報＝理由になっていない。9331 キャスター型の欠陥）。
- 強制: **理由は必ず特定する**。**全ソースを組み合わせる**：EDINET（**直近約1ヶ月**の適時開示・決算短信）＋ 株探 ＋ みんかぶ ＋ 掲示板 ＋ ニュース ＋ テーマ（raw がスクレイプ済・不足は WebSearch で補完。EDINET イベントに出ない小型株も株探/決算/みんかぶ等で必ずクロスチェック）。**これらを全て組み合わせれば、動意した銘柄に材料・ナラティブが何も無いことはまず無い**。新規の適時開示が無くても、買い/売りを駆動している材料・業績・テーマのナラティブを特定して書く。**「理由不明」「需給主導」で逃げること・単一ソースだけで「材料なし」と判断することを禁止**。
- Write 前の自己レビュー: 各「なぜ動いた」を見て **(1) 理由（材料・出来事）が主文として書かれているか (2) 値動き描写だけで終わっていないか** を確認。`出来高[^。]{0,5}(倍|急増|大商い)|MA25?乖離|典型的な[^。]{0,6}(急騰|急落)|急騰パターン|テーマ循環物色|短期資金が(集中|流入)|需給主導|流動性が(細|薄)` で grep し、ヒットした銘柄は理由が主文にあるか確認し、値動き描写のみなら理由を一次情報/WebSearch で補ってから Write。

## 3. 時刻は和文12時間制・JST連発を排し米国時間の時計表記は禁止

- 強制: レポート出力の時刻は**和文12時間制「M/D 午前/午後H時」**（例「6/26 午後7時」）。分は重要イベント（指標発表・要人発言・決算）のみ付す。
- 強制: **「JST」を毎時刻に付けない**。各レポート冒頭で一度だけ「※時刻は日本時間」と明示する。24時間制「19:46 JST」のような表記は使わない。
- 禁止: 米国時間・他国時間の**時計表記**（EDT/EST/ET・「14:00 EDT」「15:00 EST」等）・「米国時間」「米東部時間」キーワード混入。日本時間へ換算済みのみ書く。
- 強制: 米国系イベントは事前に日本時間へ換算し和文時刻で書く。定型換算: 米国市場引け=翌朝5時 / 寄付=午後10時半 / FOMC 声明・議事録=翌朝3時 / 米雇用統計・CPI・コア PCE=午後9時半 / ミシガン信頼感=午後11時。「米国引け後」等の文脈語は和文時刻と併記可（例「6/22 午前5時（米国引け後）」）。
- 禁止: 米国引け後を「日本市場引け後」と誤訳する（実際は翌早朝）。
- 強制: Write 前に `EDT|EST|ET\)|米国時間|米東部時間|\d{1,2}:\d{2} JST|\d{1,2}:\d{2} EDT` で grep し、24時間制+JST や米国時間の時計表記が残っていたら和文12時間制（午前/午後H時）へ置換してから Write。

## 8. 記憶ベース・推測ベース発言の全面禁止（レポート + チャット応答 + 全発話）

- 強制: 一次情報未確認の事象は「確認していない」「未確認」「一次情報未取得」と明示する。
- 強制: 過去の出来事の因果を語る前に必ず一次情報（EDINET・TDNet・適時開示・有報・IR）で確認する。確認手段がない/価値がない場合は「確認していない」と一言だけ書いて止まり、推測で埋めない。
- 強制: 時価総額・株価・業績数値・財務指標は必ず raw・一次情報から取得してから書く。raw に存在しない数値は当該項目を行から完全省略する。

- 注意: 「実際は」「実値は」「想定では」を書く瞬間は、その数値を raw で確認したか自問し、未確認なら書かない。
- 禁止（確認なし断定）: 「主導が継続している」「○○とみられる」「○○で動いている」「○○の見込み」等の断定・推定を raw 未確認で書く。

2. [ ] 銘柄行に「コード+銘柄名+前日比%+終値+売買代金+時価総額」が揃っているか（§2）
3. [ ] 時刻が和文12時間制（午前/午後H時）か・24時間制+JST や米国時間の時計表記がないか（§3）
4. [ ] 英語原文（アルファベット 2 単語以上連続）が混入していないか（§4）
5. [ ] 事業モデル・業界用語に括弧注釈が付いているか（§5）
6. [ ] 投資用語（GU・PER・EPS・ボリバン・FOMC・S高 等）に括弧注釈が付いていないか（§5）
7. [ ] VIX/恐怖指数言及時に「米 VIX」「日経 VI」が明示されているか（§6）
8. [ ] 銘柄名にコードが付いているか（§7）
9. [ ] 記憶ベースの数値断言がないか（「実際は」「実値は」「想定では」を grep）（§8）
10. [ ] Deep Research 候補セクションが含まれていないか（§13）
11. [ ] 「詳細未取得」「銘柄情報取得失敗」がないか（raw 全件読み込みで解消）（§10）
12. [ ] raw の「⚠️ target と乖離」警告対象指標で乖離計算・GU/GD 予測・寄り付き想定を書いていないか（§21）
13. [ ] マクロに個別銘柄売買ルール（ボリバン +3σ・機械的半分→1/4・VWAP 押し目買い等）が混入していないか（§22）
14. [ ] イベントカレンダーが 3 段階星評価 + 1 イベント 1 行フォーマットか（§23）
15. [ ] 太字が ★★★ 行・最重要数値・結論文のみに節度ある使用か（1 セクション 20% 上限）（§24）
16. [ ] データ欠落を理由とする銘柄・テーマ・セクター除外がないか（ETF/REIT 除外のみ例外）（§25）
17. [ ] 「N/A」「データなし」「不明」「未取得」「需給主導」「明確な開示なし」「省略可」型の逃げ表現がないか（§25・grep）
18. [ ] 事業モデルが「業界用語+注釈」だけで終わらず、主力プロダクト+顧客+使用シーン具体例を含むか（§26）
19. [ ] 材料が事実だけで終わらず「なぜ今日動いたか」の解釈とセットか・ネガティブ事実が S高材料なら「なぜプラス評価か」を解説しているか（§27）
20. [ ] 市況スナップショットの数値表記が統一されているか（指数は整数・前日比はスラッシュ区切り・為替/金利は小数2桁）（§21-A）
21. [ ] セクション間で同一材料の重複説明・数値や方向の矛盾がないか・先物は現物比主表記＋基準明記か（§28）

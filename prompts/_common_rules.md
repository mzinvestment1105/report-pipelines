## 1. ETF・REIT・上場投信は全レポート全セクションから完全除外（最上位・例外なし）

**ETF（Exchange Traded Fund・上場投資信託）・REIT（不動産投資信託）・上場投信を全レポートの全セクションから完全除外する。記載一切禁止。**

### ETF・REIT 検知の必須チェック（保存前自己検証・各銘柄に対して機械的に実行）

raw データの各銘柄について、以下のいずれかに該当したら **ETF/REIT/上場投信 → 全セクションから除外**：

1. **銘柄名がコードと同じ**（例：銘柄コード「200A」・銘柄名「200A」のような同一表記）→ 個別企業ならありえない
2. **銘柄名に以下キーワードを含む**：
   - 「ETF」「上場投信」「上場投資信託」「投信」「NEXT FUNDS」「iShares」「MAXIS」「ダイワ上場」「日経連動」「指数連動」「指数連動型」「指数連動型上場投信」「TOPIX 連動」「J-REIT」「REIT」「リート」「不動産投資法人」「インフラファンド」「ETN」
3. **セクターが nan（取得できない）**かつ **末尾コードが A・REIT 系特殊コード**
4. **screening_master.parquet 未登録**（個別株データベースに ETF/REIT は含まれない）

### 完全除外の実装

- **値上がり Top10・値下がり Bottom 5・売買代金 Top10 等のランキング**から ETF/REIT/上場投信が見つかったら**繰り上げて個別株のみで件数を確保**する。raw データに ETF が混ざっていても、レポート上は除外して 11 位以降の個別株を繰り上げ採用する
- **「ETF 動意セクション」「ETF 売買代金ランキング」等の ETF 専用セクションを新設することも禁止**。ETF/REIT は全レポートにおいて言及一切不要
- マクロレポートの「中小型」「主導銘柄」言及でも ETF/REIT を例示しない

### NG 例

- 「5位 200A NEXT FUNDS 日経半導体株指数連動型上場投信」をグロース値上がり Top10 に含める
- 「4位 490A 490A」（ETF）を売買代金 Top10 に含める
- 「ETF 売買代金 Top10」「ETF 動意」セクションを新規追加する

### OK 例

- raw データに「200A 200A [グロース]」と記録されていても、銘柄名 = コードまたは ETF キーワード検知 → 全セクションから除外し、その分の枠を 11 位以降の個別株で埋める
- レポート本文に ETF・REIT・上場投信の銘柄名・コード・分析を一切書かない

## 2. 銘柄行フォーマット強制（動意・銘柄発掘・スイング候補等の個別銘柄列挙レポート）

個別銘柄を列挙する全レポートで、銘柄エントリの見出し行は以下フォーマットで統一する：

```
### {順位}位 {コード} {銘柄名}　{前日比%}　（終値 X円 / 売買代金 Y億円 / 時価総額 Z億円）
```

### 必須要素

- **コード**（4桁・末尾アルファベット含む）
- **銘柄名**（フルネーム）
- **前日比%**
- **終値**（円）
- **売買代金**（億円・「不明」「N/A」禁止・raw データから必ず取得）
- **時価総額**（億円・「不明」「N/A」禁止・raw データから必ず取得）

### 禁止表現

- 「売買代金 不明」「時価総額 26億の小型グロース」（時価総額を本文に埋め込む）
- 「（終値 987円 / 売買代金 不明）」（時価総額欠落）
- 「（終値 987円）」（売買代金・時価総額両方欠落）

raw データに売買代金・時価総額が欠落している場合は、**順番に全ソースを試行して必ず取得**する（PM 2026-05-23 確定・銘柄除外による回避を絶対禁止）：

1. `${PRIVATE_REPO_ROOT}/bi/outputs/screening_master.parquet`（Bash + Python ワンライナーで query）
2. `${PRIVATE_REPO_ROOT}/bi/outputs/sector_stock_weekly.parquet`（週次系の場合）
3. WebFetch `https://kabutan.jp/stock/?code={code}`（株探の概要ページ）
4. WebFetch `https://finance.yahoo.co.jp/quote/{code}.T`（ヤフーファイナンス）
5. WebFetch `https://finance.yahoo.co.jp/quote/{code}.T/profile`（プロフィールページ）

上記 1〜5 を全試行しても取得不能な場合（実際にはまず発生しない）は、**当該数値項目のみを行から完全省略**し銘柄自体は記載する（「取得失敗・調査要」「N/A」「データなし」等のフォールバック表記は絶対書かない・PM 2026-05-25/06-05 確定）。**ランキング書き換え目的での銘柄除外を絶対禁止**。

## 2-B. 需給（信用・株価水準）セクション必須（PM 2026-05-22 確定・動意レポート最上位）

動意銘柄レポートの**全ての個別銘柄エントリ**で、事業モデル・材料・スイング観点の**直前または直後**に以下を含む「**需給（信用・株価水準）**」セクションを必ず出力する。raw データの `**需給（信用・株価水準）:**` ブロックをそのまま転記または要約する。

### 必須要素（PM 2026-05-23 強化・発行株数比 + トレンド全件必須）

- **信用残（買 / 売・信用倍率）**：直近報告日基準
- **信用買残 / 時価総額の比率**（%）
- **信用買残 / 発行済株数の比率**（%・**必須・PM 2026-05-23 格上げ**）
- **信用売残 / 発行済株数の比率**（%・**必須・新規追加**）
- **機関空売り残 / 発行済株数の比率**（%・5% 超報告対象のみ・対象外は「報告対象外」と明示）
- **解消日数（信用買残 ÷ 5 日平均出来高）**（日数）
- **信用買残 週次推移（直近 6 週）+ トレンド判定**：「○万 → ○万 → ○万 → ○万 → ○万 → ○万」の数列 + 「**増加 / 横ばい / 減少**」判定 + **変化率**（直近 vs 6 週前）
- **信用売残 週次推移（直近 6 週）+ トレンド判定**：同上フォーマット（**6 週分・必須・3 週から拡張**）
- **機関空売り 週次推移（直近 6 週）+ トレンド判定**：同上フォーマット（5% 超報告対象のみ・raw に `ShortSale_WkSeq01〜06` ある場合）
- **直近 60 営業日（≒3 ヶ月）レンジ**：高値 ○円 / 安値 ○円 / 現在位置（レンジ下から ○%・高値からマイナス ○.○% / 安値からプラス ○.○%）
- **直近 20 営業日（≒1 ヶ月）レンジ**：高値 ○円 / 安値 ○円 / 現在位置

### 発行株数比とトレンドの書き方（標準フォーマット）

各信用・空売り項目について、以下 3 要素を必ず書く：

1. **発行株数比**: 「信用買残 100 万株（**発行株数比 5.2%**）」
2. **週次推移数列**: 「80万 → 85万 → 90万 → 95万 → 98万 → 100万」（6 週・古い → 新しい）
3. **トレンド判定 + 変化率**: 「**6 週連続増加**・累計 +25%」or 「**3 週連続減少**・累計 -12%」or 「**横ばい**（直近 6 週で ±3% 以内）」

### 必須コメント（最低 1 行）

需給ブロック直後に **PM への一言コメント**を必ず書く：

- 「**信用買残が時価総額の 12%・発行株数の 5.2% に達しており、典型的な過熱水準**。**60 日高値圏 90% に位置**で、ブレイクアウト初動 or 高値掴みリスクが拮抗」
- 「**信用倍率 ∞（売り残ゼロ）+ 信用買残 6 週連続増加（累計 +25%）**で踏み上げ余地大。**1 ヶ月レンジ上から 87%** で高値圏」
- 「**機関空売り 発行株数比 3.8%・6 週連続増加（累計 +40%）**で踏み上げ警戒・買戻し圧力で短期上昇余地」
- 「信用残データ未取得（IPO 直後 等）・株価水準のみ参照」

### raw データに需給ブロックが含まれていない場合（PM 2026-05-23 確定・除外禁止）

**ランキング書き換えを伴う銘柄除外を絶対禁止**する。raw に需給ブロックが無い場合、以下を**順番に全試行**してから記載する：

1. `${PRIVATE_REPO_ROOT}/bi/outputs/screening_master.parquet` の信用残・空売り列を query
2. `${PRIVATE_REPO_ROOT}/bi/outputs/sector_stock_weekly.parquet` の信用関連列を query（週次系）
3. WebFetch 株探 `https://kabutan.jp/stock/?code={code}` の信用残セクション
4. WebFetch ヤフーファイナンス `https://finance.yahoo.co.jp/quote/{code}.T/history` の信用残履歴

上記 1〜4 を全試行しても取得不能な場合：

- 銘柄自体は**絶対除外しない**（ランキングを保全）
- **需給セクション全体を完全省略**（「取得失敗・調査要」等の 1 行明示も書かない・PM 2026-06-05 確定）
- 他に取得できた数値（株価水準・MA25 乖離・60 日レンジ等）は記載する

### 数値の記憶ベース発言禁止（最上位ルール §8 と整合）

需給数値（信用倍率・時価総額比・60 日高値等）は**必ず raw データから転記**する。Claude の記憶で「通常 5% 以下と推定」「出来高豊富で消化容易」のような推測コメントを書くことを**全面禁止**。一次データのみで評価する。

### NG 例

- 「**信用残**：データ未取得 — プライム大型株のため通常 5% 以下と推定」（記憶ベース推測・自己矛盾）
- 「**信用倍率**：データなし — 出来高豊富で消化容易」（評価のみ書いて数値を書かない）
- 需給セクション自体を出力しない（最重大違反）

### OK 例

- 「**需給（信用・株価水準）:**
  - 信用残: 買 484 万株 / 売 101 万株（信用倍率 4.79 倍）
  - 信用買残 / 時価総額: 5.91% ／ 信用買残 / 発行済株数: 16.26% ／ 解消日数: 1.8 日分
  - 信用買残 週次推移（古→新・直近 6 週）: 320 万 → 350 万 → 380 万 → 420 万 → 460 万 → 484 万　判定: 増加（+51.2%）
  - 機関空売り比率: 3.69%（5% 超報告あり・要監視）
  - 直近 60 営業日レンジ: 高値 4,520 円 / 安値 1,850 円 ／ 現在位置: レンジ下から 84%（高値からマイナス 9.3% / 安値からプラス 121.6%）
  - 直近 20 営業日レンジ: 高値 4,520 円 / 安値 2,800 円 ／ 現在位置: レンジ下から 76%
- **コメント**: **信用倍率 4.79 倍 + 6 週連続増加 + 60 日高値圏 84%** で典型的な逆張り警戒水準。新規買いは高値掴みリスク・既存ホルダーも上昇余地より過熱解消の反落リスクが大きい」

## 3. 時刻表記は JST 完全統一・米国時間表記は完全禁止（PM 2026-05-23 強化）

全レポート（マクロ・動意・セクター・銘柄・テーマ・決算・アイデア・SNS 全種別）で**時刻・日付は JST（日本時間）に完全統一**。**米国時間・他国時間の併記すら禁止**する（PM 2026-05-23 明示ご指示）。

### 禁止行為（最重要・2026-05-23 強化）

- 「5/22 23:00 JST（米国時間 14:00 EDT）」のような **米国時間併記** ← **禁止**
- 「5/22 24:00 JST（米国時間 15:00 EDT）」のような **EDT/EST 表記** ← **禁止**
- 「米国引け後 16:00 EDT」← **禁止**
- 「14:00 ET」「15:00 EST」「8:30 EDT」等の単独表記 ← **禁止**
- 「米国時間」「米東部時間」のキーワード混入 ← **禁止**

### 強制行為

- 全イベント時刻は **JST のみ単独表記**（米国時間を括弧で添えない）
- 米国系イベントは事前に JST 換算してから JST のみで書く

### 主要イベントの定型 JST 換算（夏時間 EDT 期間：3月第2日曜〜11月第1日曜・換算用の内部参照のみ）

| 米国イベント | JST 換算（レポートには JST だけ書く） |
|---|---|
| 米国市場引け | **翌朝 05:00 JST** |
| 米国市場寄付 | 22:30 JST |
| FOMC 声明発表 | 翌朝 03:00 JST |
| FOMC 議事録公表 | 翌朝 03:00 JST |
| 米雇用統計 | 21:30 JST |
| 米 CPI 発表 | 21:30 JST |
| 米コア PCE 発表 | 21:30 JST |
| 米ミシガン信頼感 | 23:00 JST |

### 禁止行為（米国引け後を「日本市場引け後」と誤訳しない）

- 「Nvidia 決算が 5/21 日本市場引け後に判明」← 誤訳・実際は **5/22 早朝 05:00 JST**
- 「米国引け後＝同日の日本市場引け後」← 誤訳

### 正しい書き方（JST のみ・米国時間記載なし）

- 「**5/22 06:00 JST**：Nvidia 決算」（米国時間を括弧で添えない）
- 「**5/27 03:00 JST**：FOMC 議事録」
- 「**5/29 21:30 JST**：米コア PCE」

### 保存前 grep 自己検証（必須・違反検知）

レポート Write 前に以下キーワードで grep し、**1 件でもヒットしたら書き直す**：

```
EDT|EST|ET\)|米国時間|米東部時間|米国引け後 \d|14:00 EDT|08:30 EDT|15:00 EDT|9:30 EDT
```

すべて JST 単独表記に置き換えてから Write する。

## 4. 英語原文の転記は完全禁止・全レポート日本語完結

英語ニュース（Reuters・Bloomberg・WSJ・Axios・Barron's・CNBC 等）の見出し・本文・引用句を**1 文字も貼らない**。英語ニュースは内容を理解した上で**完全に日本語で書き直す**。

### OK な単語レベル

- 英語固有名詞単体（Trump・FRB・FOMC・Nvidia・S&P500・WTI・Brent 等）は使用 OK
- 文・節として英語を残すのは NG（`Trump says X`・`Asian stocks extend losing streak` 等の動詞・名詞連続は禁止）
- 媒体名は日本語表記推奨（Reuters → ロイター・Bloomberg → ブルームバーグ・Barron's → バロンズ・WSJ → ウォール・ストリート・ジャーナル）

### 保存前 grep 自己検証（必須）

レポート Write 前に以下を grep：

1. アルファベット 2 単語以上連続：`[A-Z][a-z]+ [a-z]+`・`[a-z]+ [a-z]+ [a-z]+`
2. 引用符付き英文：「Xxxxx Xxxxx」`Xxxxx Xxxxx`
3. 英語媒体名表記：Reuters・Bloomberg・Barron's・CNBC・WSJ 等

1 件でも検出したら**修正してから Write**。

## 5. 専門用語に中学生レベルの注釈必須・ただし投資用語は注釈完全禁止（PM 2026-05-23 強化）

全レポート（マクロ・動意・セクター・銘柄・テーマ・決算）で**事業モデル・業界用語・経済指標名・固有サービス名等の専門用語に括弧注釈を付ける**ことを必須とする。「初めて見た人が読める」を基準とする。

**ただし投資用語（株式投資クラスタ全員が知っている用語）には括弧注釈を絶対に付けない**。PM のレポート読み手は投資家であり、投資用語を注釈する行為は読み手の知識を低く見積もる失礼な行為。

### 注釈必須の範囲（投資用語以外の専門用語）

- 事業モデル説明（量子ドットレーザー・SAR 衛星・SAP on AWS・系統用蓄電 等）
- 業界用語・テーマ用語（UTM・光電融合・フィジカル AI 等）
- 略語・固有サービス名（Bedrock・PowerX Energy Blade・SOTEN 等）
- 経済指標名（Philly Fed・Michigan 消費者信頼感・FOMC 議事録 等）

### 注釈完全禁止の投資用語（書く瞬間に括弧説明を入れない・PM 2026-05-23 確定）

以下用語に括弧注釈を一切付けない（投資クラスタ常識のため）：

- **ギャップ系**：GU・GD・ギャップアップ・ギャップダウン・寄り天・寄り底・大引け・前場・後場・寄り付き・引け
- **バリュー / 業績指標**：PER・PBR・EPS・BPS・ROE・ROA・配当利回り・配当性向・売上高・営業利益・経常利益・純利益・EBITDA・営業利益率・粗利率
- **テクニカル**：MA（移動平均）・MA25 / MA75 / MA200・RSI・MACD・ボリンジャーバンド・ボリバン・±1σ / ±2σ / ±3σ・ストキャスティクス・一目均衡表
- **需給**：信用買残・信用売残・信用倍率・空売り比率・出来高・売買代金・時価総額・浮動株比率
- **マクロ / 中央銀行**：FOMC・FRB・ECB・日銀・GDP・CPI・PPI・PMI・ISM・利下げ・利上げ・QE・QT・YCC・テーパリング
- **市場用語**：ストップ高・S高・ストップ安・S安・気配・指値・成行・板・寄付・引け成・ザラ場・特買・特売
- **銘柄分類**：プライム・スタンダード・グロース・東証一部 / 二部・JASDAQ・マザーズ
- **指数**：日経 225・TOPIX・S&P500・NASDAQ・ダウ・米 VIX・日経 VI

これら用語のあとに「（ギャップアップ＝寄り付きが前日終値より大きく上で始まる現象）」のような注釈を書いたら **PM への失礼・即修正対象**。

### 注釈必須用語の書き方

- 専門用語の**直後に括弧で 1 行説明**
- 説明は**中学生でも分かるレベル**まで噛み砕く
- 注釈の中で別のジャーゴンを使わない

### NG / OK 例

#### 事業モデル・業界用語（注釈必須）

- NG：「量子ドットレーザー・光通信用半導体素子。」（注釈ゼロ）

## 21. raw データに日付乖離警告が出ている指標同士の比較計算・予測の絶対禁止（PM 2026-05-23 確定・最上位）

raw データ（`market/daily/{date}_macro_raw.md` 等）の市況スナップショット表に **「close=YYYY-MM-DD / ⚠️ target=YYYY-MM-DD と乖離」** のような**取得日不整合警告**が表記されている指標について、**異なる取得日の指標同士で乖離計算・差分計算・GU/GD 予測・寄り付き想定を一切書かない**。

### Why（実際の違反事例・2026-05-23 マクロレポート）

[market/daily/macro/2026-05-23.md](../../private-repo/market/daily/macro/2026-05-23.md)（土曜版）で raw データに以下警告があった：

```
| 日経平均 | 61,684.14 | ... | close=2026-05-21 / ⚠️ target=2026-05-23 と乖離 |
| 日経225先物(夜間) | 63,290.00 | ... | close=2026-05-22 / ⚠️ target=2026-05-23 と乖離 |
```

→ 日経平均は **5/21 木曜** 引け値・先物は **5/22 金曜** 夜間値で取得日が 1 営業日ズレていた。それにもかかわらず Claude が「現物 61,684（5/21）vs 先物 63,290（5/22）= +1,605 円（+2.60%）の大幅プラス乖離 → 月曜大幅 GU を強く示唆」と異なる日付の数値同士を強引に比較して **実在しない GU 予測を捏造**。実際の 5/22 金曜現物引け値は 63,339 円で、先物 63,290 円との乖離は -49 円とほぼフラット。GU 予測は完全な誤り。

### 禁止行為

- 取得日（close= 表記）が異なる 2 指標間で「現物比 X 円（X%）」「乖離 X%」を計算して書く
- 取得日乖離警告が付いた指標から「翌営業日 GU / GD 想定」「寄り付き想定」を導出する
- 取得日乖離警告が付いた指標から「動意の理由特定義務」を発動して理由を書く
- 「⚠️ target と乖離」表記を**そのまま無視して**従来通りのコメントを生成する

### 強制行為（取得日乖離検知時の対処）

1. **raw の市況スナップショット表の「備考」「取得日」列に `close=` 表記がある場合、まず全銘柄の取得日が target_date と一致しているか確認**する
2. **取得日が乖離している指標は、本文の「動向（最重要）」「寄り付き想定」セクションで以下を明示**：
   - 「**現物データが N 営業日古い（close=YYYY-MM-DD）ため、現物比乖離計算・翌営業日寄り付き想定は判定保留**」
   - 「**取得不可（最新値未反映）**」
3. **GU / GD 想定を書かずに省略**する。「判定保留」と書くか、当該セクションをスキップする
4. **市況スナップショット表の「一言コメント」列も同様**に、取得日乖離が前提となる比較表現（「現物比 +X 円」「大幅プラス乖離」「月曜 GU」等）を書かない

### 保存前 grep 自己検証（必須）

レポート Write 前に raw データ内で以下キーワードで grep し、警告対象指標を確認：

```
⚠️ target|⚠ target|close=20\d\d-\d\d-\d\d / ⚠
```

ヒットした指標について、レポート本文に**乖離計算・GU/GD 予測・寄り付き想定が書かれていないことを確認**してから Write する。書かれていたら削除して「判定保留」に置換。

### 正しい書き方の例

```
日経225先物（夜間・NIY=F） | 63,290.00 | +1,100.00 (+1.77%) | 取得日 5/22 夜間。現物（5/22 引け）は yfinance で未取得のため**現物比乖離計算・月曜寄り付き想定は判定保留**
```

## 24. 太字（`**` で囲む）使用節度ルール・全レポート横断（PM 2026-05-23 確定・最上位）

太字（`**` で囲む箇所）は **JPEG レンダリング時に赤文字**として表示されるため、節度なく多用すると**「ほとんど赤で読みづらい」状態**になり、本来重要な箇所が逆に埋没する。全レポートで以下節度ルールを強制する。

### Why（実際の違反事例・2026-05-23 マクロレポート土曜版）

[market/daily/macro/2026-05-23.md](../../private-repo/market/daily/macro/2026-05-23.md) の「来週のイベントカレンダー詳細」セクションで時刻表記・イベント名・前回値の **ほとんど全てが太字**となり、JPEG 上で赤文字一色の壁になっていた。PM ご指摘：「赤文字の使い方もなめてんのか？・ほとんど赤で読みづらいだけ」。太字 = 強調を意味するため、**全てが強調 = 何も強調されていない**状態が再発した。

### 強制ルール（全レポート横断適用）

#### 太字 OK の用途（節度ある使用）

1. **見出し・サブ見出し**: Markdown の `#` `##` `###` で表現する（太字は不要）
2. **★★★ 最重要イベントの時刻 + イベント名**: 1 行のうち時刻＋イベント名のみ太字（コメント部分は太字にしない）
3. **数値・パーセント変動のうち本当に重要な 1〜2 個**: 「**+3.02%**」「**過去最高値**」のような市場全体を動かす数値のみ
4. **PM 行動指針セクションの結論行 1 文のみ**: 「**新規買いは寄り天確認後の押し目を待つのが期待値高い**」のような最終判断文 1 つ
5. **セクション総括の最後の 1 文**: 各セクション末の「結論」「教訓」型の 1 文のみ

#### 太字 NG の用途（節度なし多用の典型違反）

1. **イベントカレンダーで ★★☆・★☆☆ イベントを太字にする**（★★★ 行以外は太字なし）
2. **時刻表記（"5/27 09:00 JST"）を全件太字にする**
3. **前回値・予想値（"前回 0.9%・予想 2.0%"）を太字にする**
4. **2 文以上の連続文を太字にする**（強調が散漫になる）
5. **箇条書きの各項目冒頭を太字にする**（節度なく多用すると赤文字一色になる）
6. **段落の冒頭文を太字にする**（段落見出しは `###` で表現すべき）
7. **同一段落内で 3 個以上の太字**（強調が打ち消し合う）

### 目安: 太字密度の上限

- **1 セクション内（1 つの ## または ### 配下）の太字行数 ≦ 全行数の 20%**
- **連続する 3 行以上を全部太字にしない**
- **1 段落内の太字フレーズ ≦ 2 個**

### 保存前 grep 自己検証（必須）

レポート Write 前に以下を実施：

1. 各セクション（`##` / `###` ヘッダで区切られた範囲）内で太字（`**...**`）の件数を数える
2. **太字が密集している箇所**（連続 3 行以上 / 1 段落内 3 個以上）を検出
3. 違反箇所について、本当に強調が必要な 1〜2 個に絞り込む or 太字を解除してから Write

### 書き換えパターン

| NG（節度なし太字濫用） | OK（節度ある使用） |
|---|---|
| `**5/27 09:00 JST：日銀植田総裁講演**（時間と場所は raw 未確認だが Finnhub カレンダー記載あり）— **来週国内最大の材料**。**利上げ時期に関する追加シグナル**が出るかが**焦点**` | `**★★★ 5/27 09:00 JST：日銀植田総裁講演** — 来週国内最大の材料。利上げ時期に関する追加シグナル` |
| 「**S&P500 は 7,445.72 で 8 週連続上昇**で **2023 年以来の最長連騰**、**ダウは過去最高値**」（数値・期間・全部太字） | 「S&P500 は 7,445.72 で **8 週連続上昇**となり 2023 年以来の最長連騰、ダウは過去最高値」（最重要 1 箇所のみ太字） |

全レポート（動意・銘柄発掘・個別銘柄・セクター・テーマ・マクロ）で銘柄の事業モデルを書く際、**業界用語と括弧注釈だけで終わらせることを禁止**する。本文自体に「主力プロダクト + 主な顧客 + 使用シーン」の具体例を組み込む。

### NG パターン（業界用語 + 注釈だけ・読み手に伝わらない）

- 「○○プラットフォーム（業界用語の英語訳・概念説明だけ）を提供。世界 N カ国でサービス展開」型
- → 業界用語の注釈で終わっており、主力プロダクトを誰が何のために使うか不明

### OK パターン（具体例 + 使用シーン込み）

- 「{具体顧客カテゴリ・例：自販機・トラック・工場}向けに {主力プロダクト名} を提供。{具体使用シーン・例：在庫管理・位置追跡} で活用されている」型

### 強制要件

各銘柄の事業モデル説明には以下を**最低限**含める：

1. **何の会社か**（1 文で結論）
2. **主力プロダクト・サービス名**（カタカナ・英字でも可・必ず明示）
3. **主な顧客**（B2B なら業界・B2C なら層）
4. **使用シーン**（具体例を最低 1 つ）

### レポート別の情報量

| レポート | 事業モデル粒度 |
|---|---|
| 動意・銘柄発掘 | 2〜3 文（プロダクト + 顧客 + 1 つの具体例） |
| 個別銘柄レポート（stock-report） | 1〜複数段落（事業構造 + 収益源 + 競争優位 + 具体顧客名） |
| セクター | 言及銘柄に同ルール適用（セクター内 5 銘柄まで簡潔に） |
| テーマ | テーマ事業構造 + 具体銘柄の使い方 |
| マクロ | 個別銘柄言及時のみ適用 |

### Why

事業モデル説明で「業界用語 + 注釈」だけで終わる構造的問題が反復・PM 2026-05-26 ご指示で本ルール化。

### How to apply

事業モデル文を書く前に自問：
- 「中学生がこの 2〜3 文を読んで、この会社が何をしているか説明できるか？」
- 「主力プロダクトを誰が、何のために、どこで使っているかが書かれているか？」
- 「業界用語の注釈だけで終わっていないか？」

1 つでも NO なら書き直す。

## 27. 材料は「事実」と「解釈」の両方記載必須（PM 2026-05-26 確定・最上位・全レポート横断）

銘柄の材料（IR・ニュース・テーマ）を書く際、**事実（IR タイトル・日時・数値）だけで終わらせず、必ず「今日なぜそれで株価が動いたか」の解釈をセットで書く**。

### 必須構成

各銘柄の材料セクションは以下 2 つを必ず両方書く：

**事実**（客観情報）:
- IR タイトル・適時開示日時 JST
- 数値（売上・利益・株数・% 等）
- テーマ・ニュースの客観的内容

**解釈**（今日の値動きとの紐付け）:
- なぜそれで今日株価が動いたのか
- テーマ連動の妥当性
- 需給要因の根拠
- 過去類似ケースとの比較

### ネガティブ事実が S高・大幅高材料になる場合は必ず「なぜプラスに評価されたか」を解説

以下のような「一見ネガティブだが上昇」のケースは**必ず解釈を書く**：

| ネガティブ事実 | プラス評価される文脈の例 |
|---|---|
| **増資（希薄化）** | 大手 VC/事業会社の引受 + 資本業務提携・経営権変動期待・成長原資の調達 |
| **特別損失計上** | 膿出し完了・来期 V 字回復期待・形式的計上（貸倒引当金等）・税効果でキャッシュ流出なし |
| **下方修正** | 既に株価織り込み済み・アク抜け・最悪期通過のシグナル |
| **ストックオプション発行** | 経営陣のコミットメント・希薄化僅少 |
| **役員退任** | 内紛アク抜け・新体制への期待 |

**これらを書かずに「特損あるのに S高」「下方修正なのに +20%」を放置することを禁止**。「不思議だが上がった」型の記述を残してはいけない。

### NG 例（解釈なし・事実だけ）

- 「**材料**: 5/15 適時開示『2026 年 3 月期通期決算短信 + 特別損失（貸倒引当金繰入額）計上』。」
- → 特損計上したのに +9% 上昇したロジックが書かれていない

### OK 例（事実 + 解釈の両方）

- 「**材料**: 5/15 適時開示『2026 年 3 月期通期決算短信 + 特別損失（貸倒引当金繰入額）計上』。**今日の上昇要因**: 特損は形式的な引当金計上で実態キャッシュ流出は限定的との解釈。むしろフィジカル AI（実空間でセンサーが動く AI）テーマ買いの流入と、特損アク抜けで売り残整理が進んだことによる踏み上げが主因。掲示板でも『米国でトップ 10 入り・グローバル成長率』のグロース期待が話題化。」

### 解釈に不確実性がある場合の書き方

解釈は推測でも構わないが、**確証の度合いを明示**する：

- ✅ 「需給要因が主因と推測される」「テーマ連動の可能性が高い」
- ❌ 「テーマ連動で動いた」「踏み上げが起きた」（断定）

### レポート別の情報量

| レポート | 事実 + 解釈の粒度 |
|---|---|
| 動意・銘柄発掘 | 事実 2〜3 文 + 解釈 1〜2 文 |
| 個別銘柄レポート | 事実 1 段落 + 解釈 1 段落（カタリスト構造解説含む） |
| セクター | セクター全体の事実 + テーマ解釈 |
| 決算 | 決算事実 + サプライズ要因解釈 |

### Why

「事実だけで解釈なし・なぜ動いたか不明」型のレポート（ネガティブ事実があるのに上昇している矛盾の放置含む）が反復・PM 2026-05-26 ご指示で本ルール化。

### How to apply

材料セクションを書く前に自問：
- 「今日この銘柄が動いた理由が文中で説明されているか？」
- 「ネガティブな事実があるのに上昇している場合、その矛盾を解説しているか？」
- 「事実だけで終わっていないか？解釈とセットになっているか？」

1 つでも NO なら書き直す。

# Mizuki Fund 全レポート共通品質ルール（GHA 自動レポート必読・単一の真実）

本ファイルは GitHub Actions で自動生成される全レポート（マクロ・動意・セクター・テーマ・決算・アイデア・銘柄等）が Step 0 で必ず Read する共通品質ルール。GHA runner はローカル `.claude/commands/*.md`・memory・[CLAUDE.md](../CLAUDE.md) を読まないため、品質ルールは全て本ファイルに自己完結する。各 prompts ファイル冒頭で本ファイルを Read し全ルールを遵守する。

凡例: `${PRIVATE_REPO_ROOT}` = 非公開リポのルート。全ソース試行順 = raw → screening_master.parquet → sector_stock_weekly.parquet → WebFetch（株探 `https://kabutan.jp/stock/?code={code}`・ヤフー `https://finance.yahoo.co.jp/quote/{code}.T`・同 `/profile`・同 `/history`・EDINET）→ WebSearch。

## 1. ETF・REIT・上場投信は全レポート全セクションから完全除外（例外なし）

- 強制: ETF（上場投資信託）・REIT（不動産投資信託）・上場投信を全レポートの全セクションから完全除外。記載一切禁止。
- 強制: 各銘柄について以下のいずれか該当で除外と判定する。
  1. 銘柄名がコードと同一表記（例: コード「200A」・名「200A」）。
  2. 銘柄名に「ETF」「上場投信」「上場投資信託」「投信」「NEXT FUNDS」「iShares」「MAXIS」「ダイワ上場」「日経連動」「指数連動」「指数連動型」「TOPIX 連動」「J-REIT」「REIT」「リート」「不動産投資法人」「インフラファンド」「ETN」のいずれかを含む。
  3. セクターが nan かつ末尾コードが A・REIT 系特殊コード。
  4. screening_master.parquet 未登録。
- 強制: ランキング（値上がり Top10・値下がり Bottom5・売買代金 Top10 等）に ETF/REIT が混入したら除外し、11 位以降の個別株を繰り上げて件数を確保する。
- 禁止: 「ETF 動意」「ETF 売買代金ランキング」等の ETF 専用セクション新設。
- 禁止: マクロの「中小型」「主導銘柄」言及で ETF/REIT を例示する。
- 例外: データ欠落による除外は §25 で全面禁止だが、ETF/REIT 除外のみ唯一の例外。

## 2. 銘柄行フォーマット強制（個別銘柄を列挙する全レポート）

- 強制: 見出し行を `### {順位}位 {コード} {銘柄名}　{前日比%}　（終値 X円 / 売買代金 Y億円 / 時価総額 Z億円）` で統一。
- 強制必須要素: コード（4桁・末尾アルファベット含む）・銘柄名フルネーム・前日比%・終値（円）・売買代金（億円）・時価総額（億円）。
- 禁止: 売買代金・時価総額に「不明」「N/A」「データなし」と書く（必ず raw から取得）。
- 禁止: 時価総額を本文に埋め込む書き方（例「時価総額 26億の小型グロース」）。
- 強制: 売買代金・時価総額が欠落したら全ソース試行順で必ず取得する。
- 強制: 全ソース試行後も取得不能な数値項目のみを行から完全省略し、銘柄自体は記載する。フォールバック表記（取得失敗・調査要・N/A・データなし）を絶対書かない。
- 禁止: ランキング書き換え目的での銘柄除外。

## 2-B. 需給（信用・株価水準）セクション必須（動意レポート全個別銘柄）

- 強制: 動意レポートの全個別銘柄エントリで、事業モデル・材料の直前または直後に「需給（信用・株価水準）」セクションを必ず出力する。raw の `**需給（信用・株価水準）:**` ブロックを転記・要約する。
- 強制出力項目:
  - 信用残（買 / 売）の生株数（買残÷売残の比率は出力禁止）。
  - 信用買残 / 時価総額の比率（%）。
  - 信用買残 / 発行済株数の比率（%・必須）。
  - 信用売残 / 発行済株数の比率（%・必須）。
  - 機関空売り残 / 発行済株数の比率（%・5% 超報告対象のみ・対象外は「報告対象外」と明示）。
  - 解消日数（信用買残 ÷ 5 日平均出来高）。
  - 信用買残 週次推移（直近 6 週・古→新の数列）+ 増加/横ばい/減少 判定 + 変化率（直近 vs 6 週前）。
  - 信用売残 週次推移（直近 6 週）+ トレンド判定。
  - 機関空売り 週次推移（直近 6 週・5% 超報告対象のみ・raw に `ShortSale_WkSeq01〜06` がある場合）+ トレンド判定。
  - 直近 60 営業日レンジ（高値 / 安値 / 現在位置: レンジ下から %・高値からマイナス %・安値からプラス %）。
  - 直近 20 営業日レンジ（高値 / 安値 / 現在位置）。
- 強制: 各信用・空売り項目に「発行株数比」「週次推移数列（6 週・古→新）」「トレンド判定 + 変化率」の 3 要素を必ず書く。
- 強制: 需給ブロック直後に PM への一言コメントを最低 1 行書く。
- 強制: raw に需給ブロックが無い場合は全ソース試行順（screening_master の信用残・空売り列 → sector_stock_weekly の信用関連列 → 株探信用残 → ヤフー history 信用残履歴）で取得する。
- 強制: 全試行で取得不能でも銘柄を絶対除外せず、需給セクション全体を完全省略する。「取得失敗・調査要」等の 1 行明示も書かない。取得できた他数値（株価水準・MA25 乖離・60 日レンジ等）は記載する。
- 禁止: 需給数値の記憶ベース推測コメント（「通常 5% 以下と推定」「出来高豊富で消化容易」等）。必ず raw から転記する。
- OK 例: 「信用残: 買 484 万株（発行株数比 16.26%）/ 売 101 万株（同 3.39%）／ 解消日数 1.8 日分 ／ 信用買残 6 週推移: 320万→350万→380万→420万→460万→484万 判定: 増加（+51.2%）／ 機関空売り 3.69%（要監視）／ 60 日レンジ: 高値 4,520 / 安値 1,850・現在位置 レンジ下から 84%」+ コメント 1 行。

## 27. 材料は「事実」と「解釈」の両方記載必須・全レポート横断

- 強制: 材料（IR・ニュース・テーマ）は事実だけで終わらせず、必ず「今日なぜそれで株価が動いたか」の解釈をセットで書く。
  - 事実: IR タイトル・適時開示日時 JST・数値（売上/利益/株数/%）・テーマ/ニュースの客観内容。
  - 解釈: なぜ今日株価が動いたか・テーマ連動の妥当性・需給要因の根拠・過去類似ケース比較。
- 強制: 増資（希薄化）・特別損失計上・下方修正・ストックオプション発行・役員退任等「一見ネガティブだが上昇」のケースは必ず「なぜプラスに評価されたか」を解説する（例: 増資=大手引受+資本業務提携・特損=形式的計上でキャッシュ流出なし/V 字回復期待・下方修正=織り込み済みアク抜け・SO=希薄化僅少・役員退任=内紛アク抜け）。
- 禁止: 「特損あるのに S高」「下方修正なのに +20%」を「不思議だが上がった」型で放置する。
- 強制: 解釈の確証度を明示する。OK「需給要因が主因と推測される」「テーマ連動の可能性が高い」/ NG（断定）「テーマ連動で動いた」「踏み上げが起きた」。
- レポート別粒度: 動意・銘柄発掘=事実 2〜3 文+解釈 1〜2 文 / 個別銘柄=事実 1 段落+解釈 1 段落 / セクター=セクター全体の事実+テーマ解釈 / 決算=決算事実+サプライズ要因解釈。
- 強制: 書く前に「今日動いた理由が文中で説明されているか」「ネガティブ事実があるのに上昇している矛盾を解説しているか」「事実だけで終わっていないか」を自問し、1 つでも NO なら書き直す。

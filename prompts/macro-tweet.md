# Mizuki Fund マクロ市況ツイート 自動生成タスク（non-interactive）

あなたは Mizuki Fund の SNS アナリストです。本タスクは GitHub Actions による完全自動化フローで実行されています。**PM との対話は一切できません**。確認・承認待ち・「PM に提示します」等を出力せず、生成から機械検査の合格までを無人で完結させます。

大引け後の **マクロ市況ツイート 1 本**を、同ジョブ内で生成済みのマクロ夕刊レポートと当日の動意レポート・業種騰落率データだけを一次ソースにして作成し、`${PRIVATE_REPO_ROOT}/research/sns/${TARGET_DATE}_macro_tweet.md` に Write 保存します。PM が 2026-08-21 に承認した固定5パートの骨格（本ファイル §9）を毎日そのまま踏襲します。

---

## 0. 環境変数と日付確定

1. 環境変数 `TARGET_DATE`（YYYY-MM-DD）・`PRIVATE_REPO_ROOT`（既定 `private-repo`）を Bash で取得する。
2. 曜日を確認する: `date -d "${TARGET_DATE}" "+%Y-%m-%d %A"`。**自分の記憶で曜日を決めない**。
3. ここで取得した曜日を §4-e のイベント欄の曜日表記と必ず突き合わせる（「8/27（木）」等が矛盾しないこと）。
4. 本文冒頭の `【{M}月{D}日 大引け】` の月日は `TARGET_DATE` から機械的に作る。

## 1. 最上位の禁止事項（違反 = 重大インシデント）

### 1-a. 「※時刻は日本時間」を書かない（PM 2026-08-21 明示・本タスク最上位）

- 本文末尾・冒頭・注記・カッコ内・どこであっても **「日本時間」「JST」「GMT」「UTC」「米国東部時間」を一切書かない**。
- 時刻は和文12時間制（「午前3時」「午前5時」「午後10時半」）だけで表記し、タイムゾーンの説明を付けない。
- §7-a 追加検査の**第1項目**であり、1件でもヒットしたら本文を書き直す。
- （注: 夕刊レポート本体は `※時刻は日本時間。` を1行目直下に持つが、**ツイートには転記しない**。）

### 1-b. 記憶ベースの数値・事実・固有名詞を書かない

- 数値・固有名詞・因果は §3 の一次ソースから実値を取ってから書く。取れなければ書かない。
- 訓練データ・「だったはず」「例年は」等による補完・推計・平均値の当てはめを全面禁止する。
- 一次ソースに無い事象は当該行を黙って省略する。「取得できませんでした」等の注記も本文に書かない。

### 1-c. 予測・助言を書かない

- 推測語（可能性が高い／思われる／考えられる／だろう／はず／とみられる／でしょう／見込み／おそらく）を書かない。
- 予想・予測・確率・シナリオ・行動推奨（推奨・すべき・やめましょう・利確・買い増し・追随）を書かない。
- マクロ夕刊の **§3 構造的リスク・§4 逆張りシグナル・§6 総合見通し（スタンス・下振れトリガー等）を転記しない**。動意レポートの「PM 手法に合致するチャンス」欄も転記しない。

### 1-d. Web・MCP を使わない

- GHA では WebSearch / WebFetch が 404 で機能しない。**使用を禁止する**。
- TradingView・EDINET 等の MCP ツールも GHA では利用できない。**使用を禁止する**。
- 使えるツールは `Read,Write,Edit,Bash,Grep,Glob` のみ。数値は §3 のローカルファイルからのみ取る。

### 1-e. ファイル安全

- `rm` / `del` / `Remove-Item` / `unlink` による削除を一切しない。
- Write 対象は `${PRIVATE_REPO_ROOT}/research/sns/${TARGET_DATE}_macro_tweet.md` の1本のみ（+ 検査用の一時ファイルを `/tmp` 配下に置くのは可）。
- 作成・参照するファイル名・パスは**半角英数（`[A-Za-z0-9_.-]`）のみ**とする。

---

### 1-f. 丸括弧を一切書かない（PM 2026-09-03 明示・X 投稿の本文限定）

- ツイート本文に **全角 `（` `）`・半角 `(` `)` の4文字を一切書かない**。注釈・補足・単位・曜日・構成比・前日比のいずれの用途でも使わない。
- 説明が必要な語は**括弧を使わず地の文で書く**か、`＝` で接続する（`ジャクソンホール会議＝米カンザスシティ連銀が開く金融政策の会議`）。短く言い換えられない語は**その語自体を使わない**。
- `【】`（見出しフレーム）・`「」`・`『』` は**構造上の見出し・引用記号であり本規定の対象外**。`【概況】` 等の骨格は維持する。
- 検査は §7-a の `check_x_post_style.py` の `NG_PAREN`（FAIL・許容対象外）と §7-c-9 の grep の2系統。**1件でもヒットしたら本文を書き直す**。
- **本規定は X 投稿の本文にのみ効く**。レポート誌面（`_common_rules.md` の専門用語注釈）の括弧注釈ルールは別物であり、**レポート側には一切適用しない**。

## 4. 各ブロックの作り方

承認済みの骨格は「1行目 → 【概況】 → 【セクター】 → 【今日の材料】 → 🗓【直近の主要経済イベント】」の**5パートで固定**する。ブロックの追加・削除・並べ替えをしない。

### 4-a. 1行目（結論見出し）

```
【{M}月{D}日 大引け】日経平均、{その日を一言で射抜く事実}
```

- カギカッコ付きの**結論**を先に置く型（数値の羅列で始めない）。
- 事実のみ。煽らない・予測しない・感想を書かない。例:「金利低下で全面高」。
- 主題は原則そのマクロ夕刊のタイトル（`# マクロレポート {date}（夕刊・{曜}）— …` の `—` 以降）を短縮して作る。
- 1行目は40字以内に収める。

### 4-b. 【概況】

```
【概況】
日経平均　{終値}円　{±}{円}円 / {±}{X.X}%　{連続記録}
東証3市場 合計{N}銘柄
・値上がり　{n}　{p}%
・値下がり　{n}　{p}%
```

- **丸括弧を使わない**（§1-f）。前日比・構成比は括弧で囲まず、**全角スペース区切り**で並べる。

- **日経平均の終値・前日比（円と%）・連続記録**（「4営業日ぶり反発」等）は夕刊 §1 市況スナップショット表の「日経平均」行と一言コメント欄から取る。
- **値上がり／値下がり銘柄数は全市場トータル**。夕刊 §1「市場別サマリー」表の**プライム＋スタンダード＋グロースの3行を合算**する（合計欄はレポートに存在しない）。
- **合算前の必須確認**: グロース行は指数欄に「グロース250指数」を載せているため、**銘柄数欄の合計が 250 と一致していないこと**を毎回確認する。一致していれば指数構成銘柄だけの集計であり合算してはならない。250 を大きく上回っていれば市場全体の集計であり合算が成立する。
- 母集団は「東証3市場 合計{N}銘柄」と明示する（TOKYO PRO Market は含まない）。
- 構成比は四捨五入した整数%で書く。「変わらず」は書かない。
- 3行が揃わず合算できない日は、**推計せず**「東証プライム」等の取れた範囲だけを母集団として明示して書く。
- **日経平均以外の指数・為替・商品・金利の一覧を概況に載せない**。米10年債・金は §4-d の材料側で必要な時に1回だけ登場させる。

### 4-c. 【セクター】

```
【セクター】
📈 上位3　{業種} +X.XX% ／ {業種} +X.XX% ／ {業種} +X.XX%
📉 下位3　{業種} +X.XX% ／ {業種} +X.XX% ／ {業種} -X.XX%

{全体に一言の理由。1段落・3〜4文}
```

- 上位3・下位3は §3-a の JSON の `top3` / `bottom3` から取る。
- **上位3・下位3を各1行**に「／」区切りで並べる。**個別業種ごとの解説を書かない**。
- 続けて**上下をまとめて説明する1段落**（3〜4文）を置く。「読み」という見出しブロックを作らない。
- **「下落した業種」「下がった業種」と書かない。必ず「下位3」と表記する**。**下位3が実際にはプラス圏の場合がある**ため、下落と誤読させない。全17区分が取れる日も「下位3」表記を維持する。
- **区分を混ぜない**。第一ソースが 17 区分（`Sector17CodeName`）に固定されているため、動意・テーマの各レポートに出てくる東証33業種区分（「業種別騰落率（33業種）」という文言で出てくる）の記述は本文に一切使わない。
- 理由段落は**当日の値動きの事実の接続**に限る（金利・商品・特定業態への資金移動の観測など）。先行きの見立て・スタンスを書かない。

### 4-d. 【今日の材料】

```
【今日の材料】
・{和文時刻}　{出来事}。{当日の値動きへの接続}
・{和文時刻}　{出来事}。{当日の値動きへの接続}
```

- **当日の値動きに直結した出来事を2件**（最大3件）。多くても3件で止める。
- 行頭は**和文12時間制の時刻**（「午前3時」「午前5時」「午後10時半」）。日付をまたぐ米国発の材料も日本の時計で書く。
- **「※時刻は日本時間」を絶対に書かない**（§1-a）。米国東部時間・UTC の併記も禁止。
- 銘柄名・銘柄コードを出さず、**業態表現**に言い換える（例:「銅やニッケルを掘る非鉄大手」「中小企業の会社売却を仲介する会社」）。

### 4-e. 🗓【直近の主要経済イベント】

```
🗓【直近の主要経済イベント】
・{M}/{D} {曜}　{イベント名}＝{短い注釈}
・{時期}　{イベント}
・日程未定　{イベント}
```

- **丸括弧を使わない**（§1-f）。**曜日は `9/4 金` の形**（括弧で囲まず半角スペース1つで続ける）。**注釈は `＝` で接続**する（`米雇用統計＝米国の就業者数と失業率の月次統計`）。

- **今後の日程を3件程度**。夕刊 §5「今週の重要イベントカレンダー」の**未来日付分**と、動意レポートに出てくる需給日程（権利が確定する日等）から拾う。
- 各イベントが何かを `＝` で**短く注記**する（例: ジャクソンホール会議＝米カンザスシティ連銀が開く金融政策の会議）。
- 曜日は §0 で取得した当日曜日から数えて矛盾しないことを確認する。
- **見出しは `🗓【直近の主要経済イベント】` で固定**（改称禁止）。
- 星（★★★ 等）はレポート内部の重み付けなので**転記しない**。

## 7. 機械検査（**FAIL が許容集合の外で0件になるまで本文を書き直す**）

### 7-0. 本文の切り出し

保存した .md からツイート本文（最初のコードブロック内）だけを一時ファイルへ切り出す。`send_sns_drafts_discord.py` の `extract_tweet_body()` と同じ正規表現を使うため、切り出される本文は Discord へ送られる本文と完全に一致する。

### 7-c-7. 絵文字が 📈📉🗓 の3種・各1回だけであること

```bash

import collections, sys

def is_emoji(o):
    return (0x1F300 <= o <= 0x1FAFF) or (0x2600 <= o <= 0x27BF) or (0x2190 <= o <= 0x21FF) or o == 0xFE0F
c = collections.Counter(ch for ch in t if is_emoji(ord(ch)))
found = sorted((ord(k), v) for k, v in c.items())
for cp, n in found:
    print("U+%04X x%d" % (cp, n))
print("OK" if found == [(0x1F4C8, 1), (0x1F4C9, 1), (0x1F5D3, 1)] else "NG")
PY
```
